Anti-fragility promotion

1Classify whether a fact is volatile, source-dependent, externally governed, or user/team-specific.
2Replace copied values with a maintained object, live lookup, source handle, and freshness rule.
3Serve the current value only when the object can be resolved and policy allows expansion.
Anti-fragility does not guess the latest value. It creates the path that keeps the value current.

During anti-fragility, Baltor asks whether a copied value can drift, what source owns it, how it refreshes, when it expires, and whether a live lookup or human review is required.

volatile values TTL live lookup object promotion
What this stage does

It identifies facts that are likely to change and promotes them into objects with source handles, refresh rules, TTL, policy checks, and optional live tools.

Concrete example

Instead of storing “refunds are allowed for 30 days,” Baltor creates a refund-policy object that resolves against the current policy source before a pack is served.

Why it matters

AI workflows become brittle when they memorize changing values. Anti-fragility keeps context useful as ownership, policies, settings, and external constraints evolve.
