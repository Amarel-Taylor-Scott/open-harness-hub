# aidoneright-business-context

A CONTEXT repo in the **AI Done Right** multi-repo org: the durable **business memory** — decisions (each
with a warrant), an activity log, analytics, MCP server configs, and meeting/strategy notes. It is
"context in a repo": grounding that every surface can reference, kept separate from product code. It holds
**no product code** and is never imported — humans and agents *read* it for grounding.

## What this repo is

It exposes, as its published interface:

- **decisions-ledger** — decisions, each carrying its warrant (user-intent quote, corroboration, or a
  named principle); superseded entries are reconciled in the same change, never left to contradict.
- **activity-log** — a dated record of what happened.
- **analytics** — business metrics and read-only summaries.
- **mcp-configs** — MCP server configurations (env-var names only, never secret values).
- **business-notes** — meeting, market, and strategy notes.

## How it fits

Dependency direction is fixed by `../dev-rules-context/contracts/surface-registry.json`:

- **This repo may consume:** `dev-rules-context` only (standards, contracts, checkers, `_shared`) — via its
  published interface, never its source. It depends on no substrate or product.
- **This repo is consumed by:** `aidoneright`, `teleon`, `baltor`, `aidevobserver` — who *reference* it for
  grounding, never import it as code. Keep the exposed interface stable for them.

The authoritative, machine-readable edges live in `EDGES.md` (generated by the edge-graph-generator from
the surface registry).

## Layout

- `CLAUDE.md` — the agent operating manual (filled from the org template; inherits the 8 standards).
- `EDGES.md` — this repo's cross-repo contract: neighbors' published edges, nothing of their internals.
- `context/` — the business memory itself, organized by area (decisions, activity, analytics, notes,
  MCP configs), added as entries land.
- `README.md` — this file.

Inherited standards, the shared glossary/config, and the portable checkers live in the sibling
`../dev-rules-context/` repo — this repo does not re-declare them.

## How to work in it

1. Read `../dev-rules-context/standards/README.md`, then `CLAUDE.md`, then `EDGES.md`.
2. This is context-only — add notes and records; do not add product code, and do not import a neighbor's
   source.
3. Every decision **carries its warrant** (change-verification law). Design / brand / strategy / pricing
   decisions need clear user intent or strong corroboration, never a unilateral single-agent call.
4. When a decision supersedes an earlier one, update or archive the stale entry in the **same** change — no
   orphaned contradictions.
5. No real PII, secrets, or confidential financials; MCP configs reference env-var names only, never
   secret values.
