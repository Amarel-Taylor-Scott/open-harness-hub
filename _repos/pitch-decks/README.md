# aidoneright-pitch-decks

A CONTEXT repo in the **AI Done Right** multi-repo org: the outward-facing fundraising **story** — investor
pitch decks, the long-form investment narrative, one-pagers, and traction/metrics evidence. It is "context
in a repo": the story every investor conversation draws from, kept separate from product code and from the
internal business memory. It holds **no product code** and is never imported — humans and agents *read* it.

## What this repo is

It exposes, as its published interface (source: `../dev-rules-context/contracts/surface-registry.json`):

- **pitch-deck** — the investor pitch deck (slides + speaker narrative) for the AI Done Right portfolio.
- **investor-narrative** — the long-form investment narrative: problem, wedge, moat, why-now.
- **one-pager** — the single-page investor summary.
- **traction-metrics** — traction + metrics evidence supporting the raise (proof-first, no vanity numbers;
  every number is measured or directly computable, never hand-typed into prose).

## How it fits

Dependency direction is fixed by `../dev-rules-context/contracts/surface-registry.json`:

- **This repo may consume:** `dev-rules-context` (standards, contracts, checkers, `_shared`) and `aidoneright`
  (the parent brand's public face: `portfolio-site`, `brand`) — via their published interface only, never
  their source. It depends on no substrate or product.
- **This repo is consumed by:** nobody yet (`consumed_by: []`). Keep the exposed interface stable for when
  a surface begins to reference it.

The authoritative, machine-readable edges live in `EDGES.md` (generated by the edge-graph-generator from
the surface registry); the neighbor view is `context/edges.md`.

## Layout

- `CLAUDE.md` — the agent operating manual (filled from the org template; inherits the 8 standards).
- `EDGES.md` — this repo's cross-repo contract: neighbors' published edges, nothing of their internals.
- `context/blackbox.md` — what this repo owns (its exposes, described) and its current contents.
- `context/edges.md` — the neighbor view and the boundary rule.
- `context/` — the pitch/traction material itself, added as it lands.
- `README.md` — this file.

Inherited standards, the shared glossary/config, and the portable checkers live in the sibling
`../dev-rules-context/` repo — this repo does not re-declare them.

**Context-only, no product code.** Nothing here is importable; surfaces reference it for grounding.

## How to work in it

1. Read `../dev-rules-context/standards/README.md`, then `CLAUDE.md`, then `EDGES.md` / `context/edges.md`.
2. This is context-only — add narrative and evidence; do not add product code, and do not import a
   neighbor's source.
3. **No confidential financials or real investor PII.** Public / synthetic metrics only. Every traction
   number is measured or directly computable (name the recompute command), never hand-typed into prose.
4. Design / brand / strategy / pricing claims need clear owner intent or strong corroboration
   (change-verification law), never a unilateral single-agent call.
