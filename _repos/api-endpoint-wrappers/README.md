# aidoneright-api-endpoint-wrappers

A DEV TOOL in the **AI Done Right** multi-repo org: reusable adapters that wrap third-party, local, and
cloud API endpoints behind stable **PORTS** (the agnostic-adapter pattern), so every product calls a
**capability**, never a hardcoded host. Adapters are cost-ordered — deterministic-first, then the cheapest
capable route — with retry/backoff and a credential port in front.

## What this repo is

Product-neutral infrastructure. It exposes, as its published interface:

- **port-adapters** — one stable port per capability; provider implementations plug in behind it.
- **provider-registry** — the catalog of available providers/routes and their properties.
- **cost-gates** — budget checks that pick and bound routes by measured cost.
- **retry/backoff** — uniform resilience across providers.
- **credential-port** — resolves credentials by **environment-variable name only**, never secret values.

Consumers call the capability; swapping a provider is a registry change, not a caller rewrite.

## How it fits

Dependency direction is fixed by `../dev-rules-context/contracts/surface-registry.json` (Baltor → Teleon →
OpenHubForAI, never the reverse; every surface may consume the substrate + inherit dev-rules-context):

- **This repo may consume:** `dev-rules-context` (standards, contracts, checkers, `_shared`) and
  `shared-backend-components` (registry, primitives, codegraph, eval-harness, storage-tiers,
  credential-plane) — via their published interfaces only, never their source.
- **This repo is consumed by:** `aidevobserver`, `baltor`, `context-injection`, `scraping`,
  `shared-backend-components`, `teleon`. Keep the exposed interface stable for them.

The authoritative, machine-readable edges live in `EDGES.md` (generated by the edge-graph-generator from
the surface registry).

## Layout

- `CLAUDE.md` — the agent operating manual (filled from the org template; inherits the 8 standards).
- `EDGES.md` — this repo's cross-repo contract: neighbors' published edges, nothing of their internals.
- `context/` — per-component context (purpose, edges, paths, proofs, status), added as components land.
- `README.md` — this file.

Inherited standards, the shared glossary/config, and the portable checkers live in the sibling
`../dev-rules-context/` repo — this repo does not re-declare them.

## How to work in it

1. Read `../dev-rules-context/standards/README.md`, then `CLAUDE.md`, then `EDGES.md`.
2. Only consume a neighbor through its `exposes` list in `EDGES.md`; never import its source.
3. Add a component as its own `context/<full-word-name>/`; read shared constants from
   `../dev-rules-context/_shared/`.
4. Every new adapter is born a candidate (`serves_truth = false`) and is cost-ordered and provider-agnostic.
5. Carry a warrant for every change; run the umbrella `run_proofs`; audit consuming neighbors before and
   after a port-signature change (six surfaces depend on this repo).
