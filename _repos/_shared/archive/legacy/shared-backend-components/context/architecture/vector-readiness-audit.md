# Vector Readiness Audit

Embedding execution has two separate states:

- planned work, where the object factory has emitted `object_embedding` rows and embedding completion stubs;
- searchable vectors, where a local worker, hosted API, pgvector table, BigQuery vector index, or other vector store has actually persisted usable vectors.

The vector readiness audit keeps those states separate. A pipeline should not claim semantic search readiness merely because embedding work was planned. This is part of the [north star platform architecture](north-star-platform-architecture.md): generated objects move through canonical storage and audit gates before they are advertised as deployable primitives.

## Inputs

The audit reads:

- `embedding-completion-stubs.jsonl` from the embedding execution planner;
- optional stored vector metadata from a local worker, Postgres/pgvector export, BigQuery export, or vector service export.

Stored vector rows should include stable identifiers, dimensions, text hashes, and storage status where available. The audit can still run before vectors exist; in that case it emits a planned-but-not-ready report.

## Outputs

The auditor emits:

- `vector-readiness-summary.json`
- `vector-readiness-rows.jsonl`
- `vector-orphan-rows.jsonl`

Rows are classified as ready, missing, present-but-not-stored, or needing review. Review cases include text-hash mismatches and dimension mismatches.

## Why It Matters

At million-object scale, embeddings will be generated by multiple workers and potentially multiple runtimes. A cheap local embedding worker, a hosted embedding API, and a cloud-native vector service can all be valid choices for different tenants. The registry needs a provider-neutral way to answer:

- which objects have planned embeddings;
- which objects have stored vectors;
- which vectors are stale or mismatched;
- which stored vectors are orphans from an old run;
- which batches are safe to retry.

This is also necessary for cost control. Planned embedding rows can be priced and routed before execution, while readiness audits prove whether paid or queued work actually produced searchable vectors.

## Safety

The audit is metadata-only. It compares IDs, hashes, dimensions, and status flags. It does not need raw source text, does not call embedding providers, and does not write to a database.

Private or sensitive text should stay behind the same trust boundary used by the embedding execution profile. If a vector row cannot be verified without exposing raw text, route it for local review instead of exporting it.
