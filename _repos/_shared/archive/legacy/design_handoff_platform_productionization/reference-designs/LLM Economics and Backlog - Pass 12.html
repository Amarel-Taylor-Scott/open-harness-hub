The strategy in one line: open/cheap models for high-volume inference (classification, summarization, verification checks), frontier APIs only where frontier reasoning is measurably needed — the documented hybrid result is a 60–80% bill cut without quality loss. Model classes, never model names, live in code (S12); the class that served each answer is recorded in its receipt.

The self-hosting trap, documented. Real self-host cost runs 3–5× the raw GPU rental once ops time is priced; against budget APIs the break-even is billions of tokens/month (one published all-in figure: ~$3,240/mo for a single-A100 deployment serving what a budget API does for a few dollars). So L-selfhost is triple-gated: receipts showing provider spend ≥ 2× all-in GPU cost for 3 consecutive months, OR a privacy mandate; an open-weight model that fits the workload; and vLLM as the stack (TGI is in maintenance; Ollama stays the dev tool). Until then, Ollama Cloud's flat tiers are the zero-ops stepping stone.
Batching is a product feature, not just a discount. Baltor's verification rail re-checks thousands of facts on a schedule — the canonical batch workload. Building the batch lane once halves the platform's largest predictable spend line, and the receipts plane already meters it per key.
