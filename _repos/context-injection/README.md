# aidoneright-context-injection

A DEV TOOL in the **AI Done Right** multi-repo org: reusable context assembly, packing, memory, and
prompt-composition tooling — the **"context is everything" plumbing** every agent surface uses. It builds
context packs, compresses to fit the headroom, and injects retrieved context into prompts.

## What this repo is

Product-neutral infrastructure. It exposes, as its published interface:

- **context-pack-builder** — assembles a bounded, lineage-preserving pack from sources.
- **memory-store** — durable memory the composer reads from (synthetic / public metadata only).
- **prompt-composer** — composes the final prompt from packs, memory, and instructions.
- **headroom-compressor** — shrinks the text surface to the budget while preserving answer-critical facts,
  source handles, and held-out warnings (lossless distillation).
- **retrieval-injector** — pulls retrieved context into the prompt at compose time.

## How it fits

Dependency direction is fixed by `../dev-rules-context/contracts/surface-registry.json`:

- **This repo may consume:** `dev-rules-context` (standards, contracts, checkers, `_shared`) and
  `shared-backend-components` (registry, primitives, codegraph, eval-harness, storage-tiers,
  credential-plane) — via their published interfaces only, never their source.
- **This repo is consumed by:** `aidevobserver`, `aidoneright`, `baltor`, `teleon`. Keep the exposed
  interface stable for them.

The authoritative, machine-readable edges live in `EDGES.md` (generated by the edge-graph-generator from
the surface registry).

## Layout

- `CLAUDE.md` — the agent operating manual (filled from the org template; inherits the 8 standards).
- `EDGES.md` — this repo's cross-repo contract: neighbors' published edges, nothing of their internals.
- `context/` — per-component context (purpose, edges, paths, proofs, status), added as components land.
- `README.md` — this file.

Inherited standards, the shared glossary/config, and the portable checkers live in the sibling
`../dev-rules-context/` repo — this repo does not re-declare them.

## How to work in it

1. Read `../dev-rules-context/standards/README.md`, then `CLAUDE.md`, then `EDGES.md`.
2. Only consume a neighbor through its `exposes` list in `EDGES.md`; never import its source.
3. Add a component as its own `context/<full-word-name>/`; read shared constants from
   `../dev-rules-context/_shared/`.
4. Compression preserves lineage — answer-critical facts, source handles, and held-out warnings survive;
   tenant-private context never leaks into a shared pack.
5. Carry a warrant for every change; run the umbrella `run_proofs`; audit consuming neighbors before and
   after an interface change (four surfaces depend on this repo).
