## What Baltor is

Baltor (`baltor.ai`) is the **applied, customer-facing context product**: fully managed,
company-/department-/initiative-wide **governed context**, **powered by Teleon** as the internal
tenant `baltor-internal`. It is a standalone product with its own buyer (orgs that want managed
context), distinct from Teleon's buyer.
Source: `_repos/shared-backend-components/docs/strategy/teleon-baltor-openhubforai-portfolio.md` ("Baltor" section), `_repos/shared-backend-components/architecture/portfolio_dependency_law.json` → `layers.baltor`.

Baltor keeps enterprise agent context **verified, current, reconciled, traceable, and ready to
serve**. It does not compete as another generic agent builder; it feeds trusted context into the
agent / RAG system / workflow platform the customer already uses, and **complements rather than
replaces** systems such as Jira/Confluence, GitHub/GitLab, Glean, Onyx, Sourcegraph, and the
vector databases (Qdrant, Weaviate, Pinecone, OpenSearch).
Source: `_repos/shared-backend-components/docs/codex/baltor-clean-context.md` ("Current Product Truth"), `_repos/shared-backend-components/docs/architecture/baltor-context-fabric-product-blueprint.md` (intro + "It complements rather than replaces…").

**The moat is governance, not the technique.** Baltor governs what becomes **TRUE**; its durable
advantage is the **governed data + receipts** (provenance, signed facts, source trust, change /
revocation handling), not the algorithm. Method *specifications* can be published to the open
store without leaking the moat, because execution and governed truth stay inside Baltor.
Source: `_repos/shared-backend-components/docs/strategy/teleon-baltor-openhubforai-portfolio.md` ("Moat split" + method-hub boundary, lines 17-18, 54-58).

The product promise, verbatim from the blueprint: *"Any agent can ask for context. Context Fabric
returns the smallest safe, source-linked, versioned, policy-compliant context object or context
pack needed for the task, with relationships, history, lineage, and evidence intact."*
Source: `_repos/shared-backend-components/docs/architecture/baltor-context-fabric-product-blueprint.md` (Product promise).

Package root: **`_repos/baltor/backend/src/baltor`**. Web surface: **`_repos/baltor/frontend/`** (the built-out app + guided demos,
served by the showcase — never a skinny replacement server; see root `CLAUDE.md` "Surfaces").

## What Baltor owns (and what it explicitly does NOT)

**Owns:** customer workflows, domain-specific outcomes, source/evidence UX, receipts, customer
workspaces, vertical integrations, and Baltor-specific agents / task catalogs / business logic.

**No longer owns directly** (these were extracted to Teleon — see `edges.md`): the generic
adaptive worker runtime, PurposeTask infrastructure, runtime switching, the promotion/eval control
plane, and generic task-dashboard primitives.
Source: `_repos/shared-backend-components/docs/strategy/teleon-baltor-openhubforai-portfolio.md` ("Baltor — the applied product"), `_repos/_shared/ARCHITECTURE-MAP.md` §3.

## The correctness invariant (the spine)

Baltor's local runtime correctness invariant runs ingestion → consumption end-to-end through the
approved runtime and is proven, not asserted:

```
INGEST (CFPB decompose) → Verify (gate) → Optimize (bake-off) →
Consumption-readiness → ConsumptionService → served ContextResponse
```

The **reference result** is the answer **"10 business days"** (Reg E), with **FAQ-30 held out as a
warning** — every served fact is source-handled + receipt-lineaged + deterministic. This is proven
by `check_baltor_full_stack_perfect` and `check_cfpb_to_consumption_end_to_end`.
Source: `_repos/shared-backend-components/docs/status/baltor-current-state-and-opportunities.md` §1-2 (deterministic report from `_repos/shared-backend-components/scripts/report_current_state.py`).

The same motion also runs **as fleet work** — each stage is a CapabilityTask that executes only
after a worker wins an atomic claim: `Intake → Decomposition → Reconciliation → Anti-Fragility →
Enhancement → Verification → Consumption`.
Source: `_repos/shared-backend-components/docs/status/baltor-current-state-and-opportunities.md` §4 (`fleet_driven_pipeline`).

- **Verification gate** — the promotion barrier for served facts (`check_verification_gate.py`).
- **Enhancement / token compression** — `context_compress.py`.

  serving path (`check_optimization_harness.py`, `check_consumption_service.py`,
  `check_cfpb_to_consumption_end_to_end.py`).
- **The governance/truth machinery (the moat):**
  - **ContextOps Verification Foundry** — agents PROPOSE, Baltor DISPOSES; no agent/LLM ever
    serves a fact directly; end-to-end proven on the CFPB reference (doc-pointer
    `prompts/baltor-contextops-verification-foundry.md`).
  - **Determinism Factory** — distills deterministic rules ONLY from VERIFIED traces; consensus is
    evidence, never truth; a promoted rule preserves `distilled_from_trace_ids` (lossless);

  - **Lossless distillation** — append-only content-addressed store + lineage + rehydration +

  - **Native format preservation** — same-shape-in/out; the ORIGINAL is never overwritten; every
    verified change carries a diff + receipt (`_repos/shared-backend-components/docs/native/overview.md`).
  - **Fragile-fact watchtower + temporal fact graph** — freshness classification, stale→durable
    verification tasks, authority+freshness projection (source-of-law beats FAQ).
  Source for all of the above: `_repos/shared-backend-components/docs/status/baltor-current-state-and-opportunities.md` §4 (matching section rows).
- **Worker taxonomy + fleet supervisor** — 18 buckets classified by tools/determinism/resource/
  risk/queue/outputs; a SAFETY SPLIT means only reconciliation / native_export / distillation /

  candidates only.

## Source trust & fact adoption (the mechanics of the moat)

Baltor does not adopt a fact because one source or one model said it. Adoption rule: **≥2
independent supporting sources**, OR one source only if it is the **authoritative source of record**
(regulator, government register, court, filing, customer-designated internal authority); if sources
disagree, the fact stays OUT of served context until precedence/effective-date/scope resolve. Every
adopted fact records supporting sources, source roles, retrieved timestamps, source hashes, archive
capture status, trust score, adoption decision, refresh policy, and a **fact-state lineage** history
(`candidate_detected → one_source_found → …`).
Source: `_repos/shared-backend-components/docs/architecture/baltor-source-trust-and-adoption-policy.md` ("Adoption Rule", "Fact State Lineage").

## Product structure (from the Context Fabric blueprint)

- **Five planes:** Source · Object · Relationship · Retrieval · Control.
- **Modules:** context connectors; context object registry (`ctx://` ids); versioning/history
  (immutable versions, tombstones not deletes); context graph; artifact engine; policy/permissions;
  retrieval/indexing (exact-handle, BM25, dense/sparse/hybrid, graph, temporal, precedence, conflict
  detection, rerank); context pack builder (`implementation_pack`, `review_pack`, `compliance_pack`,
  …); agent interfaces (MCP, REST/GraphQL, A2A, webhooks, SDKs, CLI); observability/evals/feedback.
- **Product invariants:** not a raw source mirror; not only vector search; not only a chatbot UI;
  every durable claim keeps source handles; every derived artifact keeps lineage; raw expansion is
  exact-handle-only or policy fallback; local memory can PROPOSE, enterprise promotion requires
  review.
Source: `_repos/shared-backend-components/docs/architecture/baltor-context-fabric-product-blueprint.md` (Planes, Modules, Invariants).
