## The layered strategy

Pick the CHEAPEST lane that reaches the content: **official API / spec** → **raw HTTP fetch + parse** → **sitemap/feed-seeded crawl** → **headless render (CDP-attach | one-shot CLI | Playwright)** → **remote / lightweight browser for scale** → **search API (keyed)** → **agentic LLM browser (quarantined, human-gated)**. Each is one adapter row in `browser_control/`; a router selects by the capability the job needs, not by habit.

Playwright is not the whole strategy. It is one adapter in a layered browser/data-ingestion primitive architecture.
