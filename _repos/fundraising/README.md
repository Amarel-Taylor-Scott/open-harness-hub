# aidoneright-fundraising

A CONTEXT repo in the **AI Done Right** multi-repo org: the money/market **plan** — go-to-market and
fundraising strategy, investor outreach, round planning, and market sizing. It is "context in a repo": the
plan behind the raise, kept separate from the deck itself (see the sibling `pitch-decks`) and from product
code. It holds **no product code** and is never imported — humans and agents *read* it for grounding.

## What this repo is

It exposes, as its published interface (source: `../dev-rules-context/contracts/surface-registry.json`):

- **gtm-plan** — the go-to-market plan: beachhead vertical, motion, phased launch.
- **fundraising-strategy** — the fundraising strategy: round shape, targets, timeline, use of funds.
- **investor-outreach** — investor outreach tracking + materials (public-only, no confidential data).
- **market-sizing** — market sizing (TAM / SAM / SOM) for the consumption context layer.

## How it fits

Dependency direction is fixed by `../dev-rules-context/contracts/surface-registry.json`:

- **This repo may consume:** `dev-rules-context` (standards, contracts, checkers, `_shared`) and
  `aidoneright` (the parent brand's public face: `portfolio-site`, `brand`) — via their published interface
  only, never their source. It depends on no substrate or product.
- **This repo is consumed by:** nobody yet (`consumed_by: []`). Keep the exposed interface stable for when
  a surface begins to reference it.

The authoritative, machine-readable edges live in `EDGES.md` (generated by the edge-graph-generator from
the surface registry); the neighbor view is `context/edges.md`.

## Layout

- `CLAUDE.md` — the agent operating manual (filled from the org template; inherits the 8 standards).
- `EDGES.md` — this repo's cross-repo contract: neighbors' published edges, nothing of their internals.
- `context/blackbox.md` — what this repo owns (its exposes, described) and its current contents.
- `context/edges.md` — the neighbor view and the boundary rule.
- `context/` — the GTM / fundraising material itself, added as it lands.
- `README.md` — this file.

Inherited standards, the shared glossary/config, and the portable checkers live in the sibling
`../dev-rules-context/` repo — this repo does not re-declare them.

**Context-only, no product code.** Nothing here is importable; surfaces reference it for grounding.

## How to work in it

1. Read `../dev-rules-context/standards/README.md`, then `CLAUDE.md`, then `EDGES.md` / `context/edges.md`.
2. This is context-only — add plan and strategy notes; do not add product code, and do not import a
   neighbor's source.
3. **No confidential financials or real investor PII.** Public / synthetic only. Market-sizing figures are
   sourced and datable; the strategy carries warrants (change-verification law), never a unilateral
   single-agent call.
4. Every strategy decision **carries its warrant**; when a decision supersedes an earlier one, update or
   archive the stale entry in the **same** change — no orphaned contradictions.
