Ten futures, each with a trigger, a price, and a way back.

Pass 9 chose platforms; Pass 10 stress-tests the choices against what could actually happen — first users, one product spiking, hubs going viral, enterprise self-host, the real K8s entry, GPUs, EU residency, repatriation, rebrand. Every scenario names its trigger (a measurement, never a mood), the smallest response, the verified cost, and the reversal. Canonical: production/cloud/SCENARIOS.md.

S-F
The real K8s entry
triggerALL THREE: >1 host · >10 containers · an orchestration pain compose + deploy.py can't express
responseGKE Autopilot first — per-pod billing (~$0.0445/vCPU-hr) = zero bin-packing waste, no node ops, free-tier credit covers one cluster's fee. AKS = cost alternative (free control plane). EKS only if already AWS (flat $73/mo/cluster; 6× fee jump for clusters past the 14-month support window). K8s manifests GENERATED from services.json at entry — same pattern as the Caddyfile.
cost4-pod Autopilot ≈ $78–80/mo · 3-node prod cluster $450–650/mo all-in — the entry fee; hence trigger-gated
reversalimages + manifest unchanged; compose stays the dev topology forever. Provider-migration rule: gap <$5k/mo → don't migrate, optimize in place.
S-G
GPU / self-hosted inference
triggerLLM receipts show monthly provider spend ≥ cost of owned capacity, or a customer demands on-prem models
responseadd a self-hosted adapter (vLLM/Ollama) behind the LLM plane's router — callers never know. Hetzner GEX44 (RTX 4000, 20GB) for inference.
cost€184/mo+ — needs receipts proving ≥ that in provider spend
reversalroute models back to providers; the adapter is config
