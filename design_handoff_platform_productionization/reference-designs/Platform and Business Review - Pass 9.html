02 Data layer

Flexible schemas without lock-in: relational spine + JSONB for the open part; every record carries schema_version; events/receipts are append-only; migrations forward-only. Platform state graduates JSON-file → Postgres via one storage module (DATABASE_URL flips it). Analytics: events JSONL → DuckDB locally ($0) → BigQuery only when >1M events/mo or cross-product funnels demand a warehouse. The events-plane POST is the contract; warehouses are downstream sinks.

05 Anti-fragility rules now binding (S12)

  • Ports & adapters everywhere. Code outside an adapter file never names a vendor — email.send(), never resend.send(). Live adapter choice is config, not code.
  • No magic words or numbers. Every meaningful literal has exactly one home: manifest (routes/budgets/ports), scope vocabulary, realm ids, plan config, named constants. Lint flags bare literals; "where is this defined?" always has a one-place answer.
  • Naming survives rebrands. Only stable internal ids cross seams; renaming a brand touches products.js + docs, zero code.
  • Schema changes never break readers. JSONB for the open part, schema_version on every record, append-only events, forward-only migrations.
  • Switch-back is a feature. Every adoption in this doc has a recorded reversal path; an adapter that can't be swapped in a day is a defect.
