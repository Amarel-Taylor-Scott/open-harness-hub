Self-orienting local platform

One manifest. One command. Only what changed.

Pass 6 makes the platform self-understanding: a single services.json that the router, the deployer and the tunnel all read; a deploy.py that orients itself (fingerprint → diff → act → verify → receipt) and touches only what changed; one short path namespace that works identically on localhost and trycloudflare; and a vault (SOPS+age) so keys are encrypted at rest with zero servers to run.

01 The whole interface

# in production/ — every recipe is plain shell; CI calls the same ones (S5a) just vault-init # once — age keypair, outside the repo just vault-edit # secrets in $EDITOR, ciphertext-only in git just up # vault → routes → containers → status just tunnel # public https://<random>.trycloudflare.com just deploy # the 1-click: only what changed, verified, receipted just plan # dry-run — show what WOULD change

02 How the deploy orients itself

Orient
Reads services.json (what should exist), .deploy-state.json (what last shipped), and fingerprints every service's inputs.
Plan
The diff is the plan: which containers rebuild, whether routes regenerate, which host services need you to restart them — it prints the exact command instead of pretending to own your identity service.
Act
Regenerates the Caddyfile from the manifest if routes changed; compose build + up for changed containers only; reloads the gateway. Unchanged services are never touched.
Verify
Health-checks every routed service through the gateway (the path users take), with retries. An unhealthy service fails the deploy loudly — nothing is reported shipped that didn't answer.
Receipt
Appends what changed, hash before/after, and health results to dist/deploy-receipts.jsonl — HMAC-signed when CORE_SIGNING_SECRET is set, explicitly marked unsigned otherwise.

03 Short, intelligent routes

One path namespace, declared once in services.json, generated into the gateway by gen_caddy.py (with a --check drift gate for CI): /api/identity/* → your identity service on the host (9410) · /api/events/*, /llm/*, /api/core/* → platform-core · everything else → the 24 static surfaces. Code never hardcodes a port — the same relative paths work on localhost, through the tunnel URL, and later behind real DNS. Adding a service is one manifest entry; the router, deployer and health checks follow automatically.

04 The vault decision

SOPS + age (full record: production/vault/README.md). Secrets live encrypted inside the repo; the age private key lives only on your machine. No server to run, no SaaS root-of-trust, diffable, and the swap-seam is one recipe — services only ever see env vars, so graduating to OpenBao later touches vault-export and nothing else. HashiCorp Vault/OpenBao deferred until runtime rotation/leases are real needs; Infisical/Doppler rejected (external root of trust conflicts with local-first).

Honest status (G-9, G-10). All of this ships as runnable, stdlib-only files — authored here, not executed here. First validation on your machine: just plan (read-only), then just up. Fingerprints use size+mtime (fast) — tighten to sha256 when artifacts get checked in. Vault needs sops+age installed; without them it falls back to your existing .env and says so.
