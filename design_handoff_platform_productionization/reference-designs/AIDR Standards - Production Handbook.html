Frameworks · policies · standardizations

The production handbook: ten standards, each with its proof.

Everything the portfolio adopts from design to monitoring, in one place. Each standard names its rule, its enforcing check, and its honest status — adopted, partial, or proposed. The canonical text (full contracts) lives in production/standards/STANDARDS.md; the pipeline that enforces S4–S7 ships as production/ci/github-actions.yaml. Nothing below claims green without naming what proves it.

01 The standards

S1
Design system — branded house
Tokens-only color/scale, .oh-card physics everywhere, one accent per brand, zero overflow, light+dark + console clean.
proof → Design Acceptance Scorecard · hex-lint · scrollWidth probe
adopted
S2
Mode Protocol — simulated vs real actions
Every backend client has exactly live / simulated / unknown modes; simulated is clearly flagged in every record + an amber banner with the real start command; a real action is never silently faked. Reference: oh-identity.js, oh-service-auth.js.
proof → kill-backend contract test: mode flips, banner renders, records flagged
adopted
S3
API & auth conventions
Paths /api/<plane>/<realm>/… · X-AIDR-Request-Id everywhere · errors {"error":…} · raw secrets shown exactly once, hash-only storage · SERVICE_<ID>_SECRET per realm · one-directional scoped handshakes · no SSO, cross-realm rejected.
proof → check_identity_local_service_runtime 27/27 pattern · ENDPOINTS-map contract tests
partial
S4
Testing pyramid
Proof modules (backend) → contract tests (the live/simulated seam) → Playwright surface smokes (golden paths + structural probes) → held-out checks that prove the negative (cross-realm rejected, revoked key fails). A pass is named checks with counts, never "tests pass".
proof → CI test stage runs all four layers
partial
S5
CI/CD pipeline
One shape for every deployable: lint → test → build (precompiled JSX) → package (SBOM + cosign, digest-pinned) → deploy → smoke. Conventional commits, semver per service. Deploy refuses unsigned images; smoke curls every /health and fails loud.
proof → the workflow file itself + required-checks branch rule
proposed
S6
Distribution — the container thesis on our own artifacts
Digest-pinned pulls in every doc, CycloneDX SBOM + cosign signature + provenance per image, hub release pages reuse the registry provenance panel, status:'private' enforced server-side.
proof → cosign verify gate in package stage · unpinned-pull doc check
proposed
S7
Monitoring & observability
/health per service · append-only audit JSONL with request-id correlation · one events plane for analytics + A/B (anon ids, never PII) · Control Tower Deployments lane shows version/digest/health per running container · OhStatus renders from real health aggregation.
proof → CI smoke stage · events round-trip test (emit → summary increments)
partial
S8
Secrets & security policy
No fake secrets, no provider bypasses: unset key = 501 with instructions. .env.example only, gitleaks in lint, least-privilege scopes by default, dev-crypto (blake2b) flagged and never called production. Real argon2/OAuth/SSO stays owner-gated.
proof → gitleaks · 501-behavior contract tests
adopted
S9
Releases & flip-to-public
Opening a hub stays a one-line event across all three layers: products.js (brand/banner) ⇄ terraform surfaces map (DNS/tunnel) ⇄ service secrets. One key, one diff.
proof → three-map drift check (registry-drift-gate pattern, extended)
partial
S10
Documentation & honesty policy
README per folder, stable G-numbered gap ledger, pass log per increment. "SIMULATED", "CONTRACT PROPOSAL" and "skeleton — never applied" are part of the deliverable. Claims name their proof or say "not run here".
proof → status fields in STANDARDS.md · README-presence check
adopted
