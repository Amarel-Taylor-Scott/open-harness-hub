The engine

Not retrieval. A governed-context engine.

Most tools retrieve a document and hand the model whatever got fetched. Baltor runs a five-stage engine over your corpus, so what an agent reads is verified, current, efficient and provable — not just retrieved. Each stage is a peer; together they turn messy, conflicting, stale context into a governed, cited pack. Open any stage:

verified
Correct, not guessed
Reconciled to the authority; the model never decides truth.
current
Refreshes, not rots
Volatile facts anchored to live sources, re-verified on change.
efficient
Lean, still cited
Distilled to the task budget without losing fidelity.
provable
Signed & traceable
Every served fact carries a receipt and a source handle.

The pipeline

Ingest → five governed stages → serve
⇥
Ingest — sources enter with ACLs, hashes and source handles before any value is trusted.
↓
01
Reconciliation · makes it correct
Two sources disagree on the same fact; source precedence picks the enforcing authority. The loser is held out, never deleted.
Open →
↓
02
Hardening · makes it current
A volatile value becomes a refreshable object anchored to its source handle — freshness tracked, re-verified the moment the source moves. (anti-fragility)
Open →
↓
03
Enhancement · makes it complete
A bare fact gains its citation, its relationships, and any verified external source needed — a connected, defensible context object. Only sourced additions, never invented.
Open →
↓
04
Optimization · makes it efficient
Distilled to the smallest cited pack that still answers the task — three tiers from raw to hyper-efficient. Token reduction is not success unless fidelity survives.
Open →
↓
05
Verification & Receipts · makes it provable
The pack is checked against the live source and signed — every served fact carries a receipt and a source handle you can trace back to the exact clause.
Open →
↓
⇤
Serve — the governed pack flows to any agent (Claude Code, Cursor, your own), with handle expansion and a recorded receipt.
