## Why "Teleon"
Short, technical, abstract — reads like a system/runtime, not a consulting product or a manifesto. From
*telos* (purpose/end) — directly on-thesis for a purpose-driven runtime. `.dev` reads better than `.run` for a
developer platform. The name is attached to the **runtime/control plane**, not a vague "agent platform."

## Naming conflict — caution (the domain is owned; positioning must stay crisp)
The owner's name screen found **Teleon already appears in adjacent/unrelated spaces**, the most relevant being
**Teleon AI / `teleon.ai`** — positioned as a platform for deploying/managing AI agents (a GitHub `teleonAI/
teleon` SDK with `teleon dev` / `teleon deploy`). Also: **Teleon Surgical** (intraocular lenses) and **Teleon
Cybersecurity / managed IT** (unrelated). Owning `teleon.dev` does not remove the `teleon.ai` adjacency risk
for *market confusion / trademark* — so:

- **Lead with:** CapabilityTask · purpose-defined compute · runtime arbitrage · evidence-gated promotion ·
  bounded self-adaptation · human-approved boundary expansion.
- **Avoid:** "deploy AI agents in minutes" · "Vercel for agents" · "AI agent runtime" · "agent deployment
  platform" — anything that collides with the `teleon.ai` positioning.
- **Before public launch:** run registrar / WHOIS / RDAP on adjacent domains + a **USPTO/EUIPO trademark
  search** for the relevant classes; get legal clearance. Consider securing adjacents if available:
  `teleonruntime.com/.dev`, `teleoncloud.dev`, `teleonlabs.dev`, plus the standard's `capabilitytasks.org/.io`.
- **Fallbacks if legal/market confusion is unacceptable:** Captra.dev · IntentPlane.dev · RunPurpose.dev ·
  TaskPlane.dev · EvidentRuntime.dev · PurposePlane.dev · CapabilityPlane.dev.
