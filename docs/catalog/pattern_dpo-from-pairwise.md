# Direct Preference Optimization (DPO) from pairwise preferences

*pattern* · `pattern/dpo-from-pairwise` · v0.1.0 · stable

Skip explicit reward modeling + PPO; directly optimize policy against pairwise (chosen, rejected) preferences via a closed-form log-likelihood loss. Trains with the same compute as SFT — no reward model, no rollouts, no KL penalty machinery.
